# 本地会话总结

只在用户明确要求保存、记录、更新或继续某次对话时使用。目标是支持多轮连续性，不建立未经同意的人物数据库。

## 保存位置与隐私

- 将文件保存到当前项目的 `.inner-exploration/sessions/`。
- 该目录由 `.inner-exploration/.gitignore` 排除，不进入 Git；这不等于加密，仍应提醒用户它是本机普通 Markdown 文件。
- 默认使用关系称谓或用户提供的代号，不主动写入真实姓名、联系方式、住址、账号、医疗编号等身份信息。
- 只保存结构化总结，不保存完整聊天、长篇原话或聊天截图内容。只有用户明确要求保留某一句时才记录短引语。
- 用户要求查看时给出文件链接；要求删除时先确认精确文件，再执行可恢复或明确授权的删除操作。

## 触发规则

以下意图允许写入：

- “记录一下／保存本次／把今天聊的写下来”
- “更新上次的记录／把这个补充进去”
- “下次从这里继续”
- “结束这次会话并保存”

“今天先到这里”本身只触发对话整合，不自动写文件。没有保存意图时不要追问用户是否需要记录，以免每次结束都产生压力。

## 创建与更新流程

1. 先在对话中形成精简总结，区分事实与推测。
2. 使用 `scripts/session_notes.py create --title "主题"` 创建模板；脚本会返回绝对路径。同一天同标题会返回已有文件，避免重复。
3. 使用 `apply_patch` 填写或更新对应 Markdown。不要用 shell 拼接私密内容。
4. 更新时保留用户已经确认的重要内容；若理解改变，将旧假设标为“已修正”，不要静默改写历史。
5. 用户说本次结束并保存时，运行 `scripts/session_notes.py close --id "文件名"`。
6. 写入后告诉用户保存了哪些类型的信息，并提供文件链接。

## Markdown 内容约定

每份文件包含：

- **本次焦点：** 这次真正探索的问题。
- **用户确认的事实：** 只写用户陈述或明确确认的事件。
- **感受与需要：** 使用用户自己的表达；不确定时标注待确认。
- **暂定理解：** 理论解释、关系模式或假设，明确写为可修正。
- **用户认可的发现：** 用户表示贴近、有帮助或愿意保留的认识。
- **开放问题：** 尚未回答的问题，不把它们写成结论。
- **偏好与边界：** 例如不要给建议、希望直接一些，仅记录用户明确表达的偏好。
- **下次入口：** 一两句说明继续时从哪里开始。

不要记录诊断、人格定性、对第三方的读心结论或模型未经用户确认的深层解释。

## 继续已有会话

运行 `scripts/session_notes.py list` 查看标题、状态和更新时间。用户指定明确标题或文件时只读取该文件；存在多个可能时列出候选让用户选择。读取后先用两三句话说明上次停在哪里，再继续当前对话，不把整份记录原样复述。

## 脚本命令

从 skill 目录运行：

```text
python3 scripts/session_notes.py create --title "关系中的被理解"
python3 scripts/session_notes.py list
python3 scripts/session_notes.py validate --id "2026-08-17--abcd1234.md"
python3 scripts/session_notes.py close --id "2026-08-17--abcd1234.md"
```

可用 `--root` 指定其他会话目录；未指定时默认使用当前工作目录下的 `.inner-exploration/sessions/`。
